# Width-2048 QKV and FFN down replacement

English | [日本語](lm-qkv-down-2048-20261118.ja.md)

Compare all Dense, QKV only, FFN down only, and QKV plus FFN down at
seed 17 on one RTX 4090. Use the [V-allocation study](lm-qkv-v-allocation-20261117.md)
configuration and the same 4,882 updates, frozen TinyStories splits,
batch order, optimizer schedule, FP32 radius decode and GPU variance
calibration. Each replacement covers all four blocks.

| Arm | Q/K/V coefficients | Atoms per down projection |
| --- | --- | ---: |
| Dense | — | — |
| QKV only | 48 / 48 / 64 | — |
| FFN down only | — | 393,216 |
| QKV plus FFN down | 48 / 48 / 64 | 393,216 |

FFN down maps 8,192 inputs to 2,048 outputs. Use coefficient 96, as in the
[width-1024 replication](lm-fp32-seed-replication-20261117.md), so the Atom count
doubles from 196,608. Check the common Dense initialization against the
prior width-2048 study and the QKV-only initialization against the
V-allocation study for each seed. Verify matched initial Atom tensors
between the single and combined replacements.

Before the full run, compare the first projection of each replacement arm
against the independent FP64 factor oracle for output, input gradient, and
all four raw Atom gradients. The down-only arm probes the rectangular map.
Compare the first rectangular GPU initialization with the CPU initializer,
and check the first q update at every replaced projection. Benchmark 24
synchronized complete updates after 10 warmup updates per arm from
separate copies of the seed-17 starting state. Report median update time
and peak PyTorch allocated and reserved memory.

Report the per-arm final development and story-disjoint confirmation CE,
update latency, and allocator peaks. Use seed 17 as a screen. Replicate
the four arms at seeds 23 and 42 if no other arm matches or improves
on both the combined arm's confirmation CE and median update time while
strictly improving at least one. The screen uses measured point estimates.

## Reproduction

Extend the width-2048 source snapshot by the torchcst manifest recorded
in the registry. Build the private width extension for SM89 and point
TORCH_EXTENSIONS_DIR at the build directory. PAIR_ANCHOR is the completed
width-2048 c64/c128 summary, and QKV_ANCHOR is the completed V-allocation
summary. Each phase uses a separate output directory.

~~~sh
export PYTHONPATH="$SNAPSHOT/torchcst/src:$SNAPSHOT/torchcst:$SNAPSHOT/cst-research/src"
python scripts/run_lm_qkv_down_2048.py --reference-run "$REFERENCE_RUN" \
  --paired-anchor "$PAIR_ANCHOR" --qkv-anchor "$QKV_ANCHOR" \
  --source "$SNAPSHOT" --merged-manifest "$MERGED_MANIFEST" \
  --output "$OUTPUT" --phase pilot
~~~

Use --phase replication for seeds 23 and 42 and --resume to resume a
phase with identical inputs and its existing output directory.

## RTX 4090 results

The width-2048 down projection passed the independent output and gradient
check with maximum relative L2 error 1.74e-06. The first down
GPU initialization matched the CPU initialization bitwise. The first
q update passed in all twelve QKV sites, four down sites and sixteen
combined sites. The allocator measurements distinguish peak allocated
and peak reserved memory. All twelve CUDA tile-boundary regression cases
passed on the same RTX 4090.
