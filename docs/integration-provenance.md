# Integrated research workflows and preserved measured sources

English (canonical) | [日本語](integration-provenance.ja.md)

This integration brings the separately reviewed research consumers into a common
repository tree. It preserves the original commits as merge ancestors and changes
neither a running job's source snapshot nor its data/protocol identity. It is not
a GPU rerun, raw-result revalidation, completed primary assessment or adoption of
an experimental change into torchcst. No operator/backend/kernel runtime is copied.

## Completion is specific to the prespecified scope

Coordinate LR, depth13 and fixed-gain3 are marked COMPLETED because their bounded
execution, retrieval and independent raw checks finished. Their actual source,
manifest and passed-summary audit identities are in their registry `execution`
records and [observations and limitations](bounded-validation-results.md).
Completion does not imply a positive outcome: coordinate q10 did not consistently
improve the longer followups; smallest all-layer stock depth stalled; gains only
partly rescued it. Failed componentwise diagnostics, post-hoc admission scope,
reader failures and conditioning/capacity uncertainty remain disclosed. The later
[positive-gain clarification](positive-gain-equivalence.md) proves the same global
ideal-real function family for this exact architecture; it is data-free analysis,
not another training result.

HIGGS primary, the matched DST comparison and Covertype remain RUNNING. Included
assessment code does not imply it has run. The fixed primary30/comparison78 gates
and Covertype all9 seal/raw-admission gate must finish before their respective
confirmation/heldout evaluations. Preserve original-family and comparison-family
boundaries, and never use evaluation outcomes to change frozen selection rules.
The official tests remain reserved.

## Reproduce a measured run from its measured tree

Use the table's exact consumer commit and its matching external source/data
manifests, read the applicable resource instructions and choose fresh output/state
locations. The combined tree has a new source identity: it cannot satisfy an old
consumer manifest by relabeling it. Continuing existing jobs uses their unchanged
original snapshots. Reproducing from the integrated tree requires a separately
frozen consumer manifest and admission; it is distinct evidence.

CPU tests, registry checks and package validation exercise the combined code and
metadata. Actual975 CPU fixtures test public model ownership, optimizer/retraction
and checkpoint contracts when explicitly configured; they do not reproduce the
GPU trajectories or reopen evaluation data. Raw data, models, credentials and
machine-specific operational helpers remain in ignored external evidence under
the [evidence convention](reproducibility.md). Historical protocols retain their
mathematics/budgets; updated status preambles point to subsequent measured results.
